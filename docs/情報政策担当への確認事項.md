# 情報政策担当への確認事項チェックリスト

職員検診の受検票作成をアプリ化するにあたり、**着手前に確認しておくべき事項**をまとめたものです。
ここでの回答によって作れるものが変わるため、開発を始める前にご確認ください。

そのまま照会文書の別紙としてお使いいただけます。

## あわせて説明できるようにしておくとよい点

照会の際、先方の懸念を先回りして示せると話が早く進みます。

- **外部通信を一切行わない**　インターネット上のライブラリ（CDN）を読み込まず、外部へ送信も行いません。
  ブラウザの開発者ツールのネットワークタブで、通信が発生していないことを実際にお見せできます。
- **インストールが不要**　ファイルをブラウザで開くだけで、レジストリや Program Files に何も書き込みません。
- **個人情報を端末に保存しない**　名簿はブラウザのメモリ上でのみ処理し、閉じれば消えます。
  端末に残るのは判定ルールと日程の設定のみです。
- **既存業務の置き換えであり、新規の情報収集ではない**　現在 Access で行っている処理と、
  扱う情報の範囲は変わりません。
- **中身が読める**　バイナリではなくテキストファイルなので、内容を確認いただけます。

## 現行 Access からの移行にあたって用意しておくもの

アプリ側の仕様を固めるために、担当課で以下を手元に用意してください。

- [ ] 現行 Access のテーブル定義（フィールド名・型の一覧）
- [ ] 対象者抽出クエリの SQL（Access のクエリを「SQL ビュー」で開くとテキストで取り出せます）
- [ ] 現行の受検票レポートの出力見本（PDF または紙）
- [ ] 4 検診それぞれの対象者判定ルールを文章化したもの
      （年齢基準日／対象年齢／性別／毎年か隔年か／前年度受診歴の扱い／胃がんの X 線・内視鏡の選択）
- [ ] 各検診の実施根拠（労働安全衛生法に基づく定期健康診断か、共済組合・互助会の事業か）
